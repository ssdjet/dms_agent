# Локальный интерфейс и HTTP API

## Запуск

Установите зависимости в виртуальном окружении:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[test]"
```

Запустите локальный сервер:

```powershell
python -m dms_pipeline.web
```

Откройте <http://127.0.0.1:8000>. Допускается изменить порт:

```powershell
python -m dms_pipeline.web --port 8081
```

Сервер принимает только loopback адреса (`127.0.0.1`, `localhost`, `::1`) и
отвергает другие адреса для `--host`. Приложение использует Flask development
server (`debug=False`), поэтому это не production deployment.

## Путь пользователя

1. Выберите книгу `.xls`/`.xlsx` размером не более 20 МиБ.
2. Укажите строку заголовков. Для нескольких листов выберите требуемый лист.
3. Нажмите **«Считать столбцы»**. Интерфейс показывает названия столбцов,
   количество строк и лист, но не показывает данные строк.
4. Выберите один или несколько разных столбцов для кода услуги, диагноза,
   суммы.
5. При необходимости заполните утверждённые справочники и/или лимит. Оставьте
   поле пустым, если нет утверждённого источника для этого правила.
6. Запустите проверку и проверьте сводку, затем откройте нужную строку по её
   исходному номеру в вашей локальной таблице.

Пустые справочники и незаполненный предел имеют статус «не оценено». В таблице
сработок отображается только номер исходной строки, статус, идентификатор
проверки и статическое сообщение правила.

## HTTP API

Все адреса относятся к тому же локальному серверу. Запросы передачи файла
используют `multipart/form-data`.

### `GET /api/health`

Проверка готовности сервера:

```json
{"status":"ok"}
```

### `POST /api/inspect`

Поля формы:

| Поле | Обязательное | Описание |
|---|---:|---|
| `file` | да | Файл с расширением `.xls` или `.xlsx`. |
| `header_row` | нет | Номер строки заголовков; по умолчанию `1`. |
| `sheet_name` | нет | Имя листа. Если лист один, он выбирается автоматически. |

Обычный ответ содержит `sheet_names`, `sheet_name`, `columns`, `row_count` и
`source_sha256`. Если листов несколько и ни один не выбран, ответ содержит
`needs_sheet_selection: true`, список листов и пустой список `columns`.
Заголовки и SHA-256 могут быть идентифицирующими метаданными — не публикуйте
их без необходимости.

### `POST /api/analyze`

Обязательное поле — `file`. Дополнительные поля:

| Поле формы | Описание |
|---|---|
| `header_row` | Номер строки заголовков; по умолчанию `1`. |
| `sheet_name` | Имя листа, обязательно для книги с несколькими листами. |
| `service_code_column` | Исходный заголовок, отображаемый на `service_code`. |
| `diagnosis_column` | Исходный заголовок, отображаемый на `diagnosis`. |
| `amount_column` | Исходный заголовок, отображаемый на `amount`. |
| `service_codes` | Допустимые значения, каждое на отдельной строке. |
| `diagnosis_codes` | Допустимые значения, каждое на отдельной строке. |
| `maximum_amount` | Конечное число, может использовать точку или запятую. |

Нужно выбрать хотя бы один столбец. Один исходный столбец нельзя связать с
несколькими целями.

Успешный ответ имеет поля:

- `source_sha256`, `sheet_name`, `rows_checked`;
- `summary`: количества строк `pass`, `fail`, `not_evaluated`;
- `rules`: статический идентификатор, отображаемая подпись и числа исходов;
- `findings`: до 1000 строк, которые не получили итоговый статус `pass`;
- `findings_total` и `findings_truncated`.

Пример ответа только на синтетических значениях:

```json
{
  "sheet_name": "Synthetic",
  "rows_checked": 2,
  "summary": {"pass": 1, "fail": 1, "not_evaluated": 0},
  "rules": [
    {
      "rule_id": "amount_maximum",
      "label": "Сумма не превышает заданный лимит",
      "pass": 1,
      "fail": 1,
      "not_evaluated": 0
    }
  ],
  "findings": [
    {
      "row_number": 3,
      "status": "fail",
      "findings": [
        {
          "rule_id": "amount_maximum",
          "label": "Сумма не превышает заданный лимит",
          "status": "fail",
          "message": "value exceeds the configured maximum"
        }
      ]
    }
  ],
  "findings_total": 1,
  "findings_truncated": false
}
```

API возвращает ошибки пользовательского ввода/обработки книги с HTTP 400.
Загрузка больше лимита получает HTTP 413. Текст ошибок намеренно не включает
содержимое записей.

## Ограничения

- Результаты не персистентны: после завершения запроса сервер не сохраняет
  выгрузку аудита или конфигурацию.
- Колонки в `/api/inspect` возвращаются как заголовки листа; не помещайте
  чувствительные данные в заголовки.
- Анализ выполняется синхронно внутри запроса. Для крупных файлов время ответа
  зависит от библиотек/книги; отдельного worker queue, отмены и прогресса нет.
- В ответе анализа возвращается SHA-256 точных байтов файла. Хеш обеспечивает
  воспроизводимую ссылку на вход, но может связать результаты с известным
  файлом.
- При ошибке парсинга пользователь получает безопасное общее сообщение.
  Подробности ошибки намеренно не сериализуются в HTTP-ответ.
