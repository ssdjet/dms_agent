# Архитектура и путь данных

## Назначение

Проект разделяет техническую обработку реестра на независимые этапы:

1. **Чтение** фиксирует байтовую идентичность файла, выбирает лист и выделяет
   строки относительно явно выбранной строки заголовков.
2. **Сопоставление** переводит исходные подписи колонок в стандартные названия,
   не изменяя значения.
3. **Правила** дают детерминированный результат по каждой настроенной проверке.
4. **Аудит** сводит результаты для одной строки без сохранения её полей.
5. **Представление** агрегирует статусы и показывает номера строк, не значения
   исходных ячеек.

Схема отражает направление потока; ячейки Excel не сохраняются как постоянное
состояние приложения:

```mermaid
flowchart LR
    U[Браузер: файл и настройки] --> W[Flask API]
    W --> T[Временный файл]
    T --> I[ingestion: Excel и SHA-256]
    I --> M[mapping: стандартная запись]
    M --> R[rules: результат каждого правила]
    R --> A[audit: статус строки]
    A --> G[Агрегаты и номера строк]
    G --> U
    T -. удаление после ответа .-> W
```

## Модули и границы ответственности

### `ingestion.py`

- `WorkbookReadConfig` задаёт лист, строку заголовков, требуемые колонки и
  обработку пустых строк.
- `read_workbook()` читает данные `.xlsx` или `.xls` и возвращает `WorkbookData`.
- `WorkbookRow.row_number` — номер в исходном листе с единицы; пропущенные пустые
  строки не сдвигают последующие номера.
- `sha256_file()` читает файл частями, поэтому не загружает весь файл только
  ради хеширования.
- `workbook_sheet_names()` извлекает только имена листов.

Читатель не знает доменную схему. Все заголовки должны быть непустым текстом;
повторы проверяются без учёта регистра. При нескольких листах пользователь
или вызывающий код обязан выбрать один.

### `mapping.py`

`FieldMapping` содержит точную пару `source -> target`. Целевые поля должны быть
уникальны. `map_row()` выбрасывает `MappingError`, если в записи отсутствует
исходная колонка, либо если явно обязательное целевое значение равно `None` или
пустой строке. Функции не нормализуют и не приводят значения типов.

### `rules.py`

Каждое правило возвращает `RuleResult(rule_id, status, message)`. Результат
содержит описание исхода, но не значение записи. `RuleEngine` применяет правила
в стабильном порядке. Подробнее о сравнении значений см. в
[руководстве по конфигурации](configuration.md).

### `audit.py`

`create_audit_event()` получает SHA-256, исходный номер строки и последовательность
`RuleResult`. Агрегированный статус — `fail`, если хотя бы одно правило не
прошло; иначе `not_evaluated`, если правил нет или хотя бы одно не было
оценено; во всех остальных случаях `pass`.

`serialize_audit_event()` выдаёт компактный JSON с сортированными ключами. Он
не включает запись, столбцы, значения полей, причины отказа от страхового
покрытия или текст исходного файла.

### `config.py`

`load_config()` читает YAML с `yaml.safe_load`, проверяет форму и отвергает
неизвестные ключи. Функция собирает `PipelineConfig`, но сама не читает Excel и
не запускает проверки.

### `web.py` и `static/`

Flask создаёт интерфейс и API. `web.py` — адаптер: он валидирует ввод,
использует ingestion/mapping/rules/audit и формирует безопасное для отображения
представление. `static/` содержит самостоятельные HTML/CSS/JavaScript без
внешних CDN.

## Основные типы и обработка ошибок

- `CellValue` описывает поддерживаемые скалярные значения Excel.
- `WorkbookData` хранит хеш, выбранный лист, заголовки и строки прочитанной
  книги в оперативной памяти.
- `PipelineError` объединяет ожидаемые ошибки. `WorkbookReadError`,
  `WorkbookValidationError`, `MappingError` и `ConfigurationError` дают
  вызывающему коду типизированное различение ошибок.
- В веб-API ошибки обработки файла возвращаются с безопасным обобщённым текстом;
  ввод пользователя с ошибками возвращается как HTTP 400, превышение лимита
  загрузки — HTTP 413.

Не добавляйте `except Exception` вокруг бизнес-логики: неожиданные ошибки должны
оставаться видимыми для разработчика и тестов. При этом не помещайте в логи
или сообщения пользователю содержимое строки, имя пациента или номер полиса.

## Принципы расширения

- Новые доменные правила добавляйте как отдельные небольшие типизированные
  реализации контракта `Rule`; не смешивайте чтение Excel и оценку политики.
- При изменении схемы импорта обновляйте тесты `.xls` и `.xlsx`, если изменение
  применимо к обоим форматам.
- Используйте явные справочники и пределы. Не выводите медицинскую или
  страховую политику из примеров, случайных наборов или данных одного реестра.
- Аудит предназначен для воспроизводимости проверки; не включайте в событие
  больше идентификаторов, чем нужно для отладки и поиска исходной строки.
