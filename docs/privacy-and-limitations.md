# Конфиденциальность и ограничения

## Какие данные проходят через приложение

Во время запроса сервер получает загруженный workbook и временно держит его в
каталоге `TemporaryDirectory`. Парсер читает заголовки и значения выбранного
листа; правила выполняются для каждой строки в памяти. После завершения или
ошибки контекст временного каталога удаляется.

Файл исходного пользователя не меняется. Приложение не удаляет файл из папки
пользователя, вложений, резервной копии, облачного синхронизированного каталога
или файловой системы браузера. Удаление временного каталога не гарантирует
криптографического/физического уничтожения блоков накопителя.

## Что может попасть в ответ

API возвращает:

- список листов и названия колонок в `/api/inspect`;
- количество строк и SHA-256 источника;
- имена статически известных правил, статусы и обобщённые сообщения;
- номера строк исходной книги, у которых общий статус не `pass`.

Значения полей (включая ФИО, номер полиса, диагноз, код услуги, сумму и
комментарии исходной строки) намеренно не копируются в результат или событие
аудита. При этом заголовки, хеш и номер строки могут быть идентифицирующими
метаданными. Получайте и передавайте результаты только в подходящем
защищённом контексте.

`source_sha256` вычисляется по точным байтам книги и возвращается браузеру;
интерфейс показывает только первые 12 символов в подзаголовке.

## Защитные настройки прототипа

- Loopback по умолчанию и запрет другого значения `--host`.
- Лимит загрузки 20 МиБ.
- Случайный временный каталог с автоматическим удалением после запроса.
- Сервер не включает режим Flask debug.
- Ограничивающие браузерные заголовки: CSP `self`-only, `nosniff`,
  `frame-ancestors 'none'`, `X-Frame-Options: DENY`, `Referrer-Policy:
  no-referrer`.
- Статические HTML/CSS/JavaScript обслуживаются самим приложением, без внешнего
  CDN.
- В интерфейсе ошибки обработки workbook не содержат исходные ячейки или
  содержимое исключения.

## Чего в прототипе нет

Нет аутентификации/авторизации, CSRF-токенов, TLS, ролевой модели, защиты от
локальных процессов с доступом к машине, сетевого аудита, rate limiting,
персистентного журнала, шифрования временных файлов или гарантированного
безопасного стирания. Ограничения не превращают Flask development server в
production-сервис.

Не запускайте приложение с сетевым интерфейсом и не добавляйте к нему
порт-форвардинг/туннель. Для многопользовательской эксплуатации требуется
отдельное моделирование угроз, инфраструктурное решение по хранению/удалению,
аутентификация, авторизация, TLS, аудит доступа, управление секретами,
ограничение ресурсов и утверждённый процесс работы с медицинскими данными.

## Обработка Excel

- Для `.xlsx` включён `read_only=True` и `data_only=True`: парсер читает
  сохранённые результаты формул, а не вычисляет формулы. Непересчитанные в
  Excel формулы могут читаться как `None`.
- Для `.xls` `xlrd` загружает workbook в память. Лимит HTTP-файла не является
  гарантией верхней границы используемой памяти.
- Макросы не исполняются. Однако значения Excel все равно следует считать
  недоверенным вводом; не добавляйте их в HTML через `innerHTML`, сообщения
  исключений, shell-команды или логи.
- Текст заголовков показывается/передаётся в UI. Не используйте в заголовках
  персональные данные.
- Слишком большие результаты ограничивают отображение первыми 1000 строками,
  но подсчёты выполняются для всех строк и включают полное число сработок.

## Безопасная отладка и тестирование

- Используйте синтетические, детерминированные фикстуры.
- Не печатайте записи при разборе настоящих workbook; при необходимости
  проверяйте только форму результата, число строк, статус и тип значения.
- Не сохраняйте таблицу соответствия ФИО и псевдо-ID в том же каталоге, что
  результаты.
- Не добавляйте настоящие книги, хеши или данные к Git-репозиторию.
- Проверьте конфигурацию справочников и лимитов по утверждённому источнику:
  успешная техническая проверка не означает принятие страхового решения.
