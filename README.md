# DMS Claims Pipeline

Локальный прототип конвейера проверки реестров медицинских услуг. Он читает
Excel, позволяет явно сопоставить столбцы с полями и выполняет только те
технические проверки, для которых настроены исходные данные. Результат
показывает статус по каждой строке и сводку по правилам, не копируя значения
строк в интерфейс.

> **Важно.** Это основа для проверки качества данных, а не система принятия
> решений о страховом покрытии. В проекте нет утверждённых программ, справочников
> кодов или финансовых порогов: не включайте такие проверки без их согласования
> с владельцем соответствующей политики.

## Быстрый старт

Требуется Python 3.10 или новее.

1. Если сейчас видите приглашение `>>>`, введите **только** `exit()` и нажмите
   Enter. Не вводите команды установки или Windows-команды в это окно Python.
2. Откройте отдельное окно **PowerShell** или **Windows Terminal** через меню
   «Пуск». Убедитесь, что `>>>` исчезло и приглашение выглядит примерно так:
   `PS C:\...>`.
3. В PowerShell перейдите в корневую папку репозитория. Замените путь-пример
   ниже на фактическую папку, где находится этот проект:

```powershell
Set-Location -LiteralPath 'C:\Users\...\dms_agent'
```

Оставаясь в PowerShell в папке репозитория, установите пакет с зависимостями
интерфейса и тестов:

```powershell
python -m pip install -e ".[test]"
```

Затем запустите локальный интерфейс из той же папки PowerShell:

```powershell
python -m dms_pipeline.web
```

Откройте <http://127.0.0.1:8000>. Выберите файл `.xls` или `.xlsx` размером
до 20 МиБ, укажите лист и строку заголовков, затем выберите доступные столбцы.
Справочники кодов и максимальная сумма необязательны. Пустая настройка означает
«не оценено», а не автоматическое одобрение.

Подробное руководство: [запуск и интерфейс](docs/web-interface.md).

## Возможности

- Потоковый SHA-256 исходных байтов файла.
- Чтение `.xlsx` в read-only режиме через `openpyxl`; чтение старых `.xls`
  через `xlrd`.
- Явная проверка листа, строки заголовков, уникальности заголовков и наличия
  настроенных колонок.
- Точное отображение исходных названий столбцов в выбранные стандартные поля.
- Настраиваемые проверки форматов, диапазонов, программ/справочников, связей,
  уникальности, последовательности визитов, количества и частоты услуг.
- Пакетные проверки с явной конфигурацией порогов; правила без нужной политики
  или справочника возвращают `not_evaluated`.
- Детерминированные результаты и JSON аудита без содержимого исходных ячеек.
- Локальная панель результатов по строкам и правилам.

Поддерживаются отдельные модули для использования без веб-интерфейса.
Справочник конфигурации и семантика правил описаны в
[руководстве по конфигурации](docs/configuration.md).

## Конфиденциальность и ограничения

- Сервер по умолчанию слушает только `127.0.0.1`; не публикуйте его в локальной
  сети или интернете.
- Загруженный файл временно хранится на сервере только на время HTTP-запроса;
  после запроса временный каталог удаляется. Исходная копия в браузере и сам
  файл на диске пользователя этим не удаляются.
- В ответах анализа содержатся SHA-256 файла, лист, статусы правил и номера
  строк, но не значения исходных ячеек. Идентификатор строки может оставаться
  чувствительным в конкретном контексте.
- XLSX читается с `data_only=True`: формулы заменяются сохранёнными Excel
  результатами; если книга не пересчитывала формулу, сохранённый результат
  может отсутствовать.
- XLS загружается библиотекой в память целиком. Ограничение веб-загрузки
  составляет 20 МиБ, однако объём памяти и время обработки зависят от структуры
  книги и количества строк.
- Это демонстрационное однопользовательское приложение. Нет аутентификации,
  ролей, фоновых задач, персистентного журнала, экспорта результатов,
  гарантированного стирания данных на физическом носителе или сопровождения
  политики покрытия.

Расширенные рекомендации и угрозы: [конфиденциальность и ограничения](docs/privacy-and-limitations.md).

## Разработка

Запустить тесты:

```powershell
python -m pytest -q
```

Все тестовые книги синтетические; настоящие медицинские, персональные или
страховые данные не должны попадать в фикстуры, логи и снимки интерфейса.
Соглашения по тестированию, сборке и расширению правил собраны в
[руководстве для разработчиков](docs/development-and-tests.md).
